# 4-DoF roll/pitch-locked loop corrections — implemented, committed, rerun on 538

**Date:** 2026-07-16 morning. Branch: `nora-altitude-fusion` in `ORB_SLAM3/` (commits `1dd3881`
night-session fusion work, `333d23a` the 4-DoF hardening).

## What "implement 4-DoF" turned out to mean

Auditing the full inertial loop-closure chain showed upstream ORB-SLAM3 is *already designed*
4-DoF end-to-end: detection requires VIBA2 (`NewDetectCommonRegions` early-return), the accepted
loop's world correction gets roll/pitch zeroed and scale pinned to 1, the pose graph is
`OptimizeEssentialGraph4DoF` (`VertexPose4DoF` = yaw+translation), and the GBA is
`FullInertialBA` (IMU edges keep gravity honest). The one gap: the roll/pitch zeroing was
**conditional** on sensor type AND `GetIniertialBA2()` — currently unreachable in the unlocked
state only because detection happens to be gated on VIBA2 elsewhere.

**Change (`LoopClosing.cc`, commit `333d23a`):** the yaw-only projection now applies
**unconditionally** on every accepted inertial loop (roll/pitch discarded, translation + yaw
kept, scale 1), decoupled from the detection-side gating, with a `[4DoF]` log line for audits.
Together with the env-configurable gate (`ORB_LOOP_RP_TOL`/`ORB_LOOP_YAW_TOL`), accepting
roll/pitch-mismatched loops is now provably tilt-safe.
